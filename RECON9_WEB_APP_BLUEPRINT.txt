# RECON 9 - Web Application Blueprint

## Project Overview

**Name:** Recon 9  
**Type:** Advanced OSINT (Open Source Intelligence) Web Platform  
**Version:** 9.0  
**Target Users:** Security professionals, penetration testers, system administrators, OSINT investigators  
**Core Purpose:** A comprehensive, browser-based reconnaissance platform that provides 37+ security and intelligence tools for DNS analysis, network scanning, IP/WHOIS lookups, web analysis, and external tool integration — all accessible through a modern, responsive web interface.

**Key Differentiator:** Instead of exporting results to separate HTML files, Recon 9 operates entirely as a web application with real-time graph visualization, interactive node exploration, and a persistent dashboard for managing scans and results.

---

## Architecture

### Technology Stack

**Backend:**
- **Framework:** FastAPI (Python 3.10+) or Node.js with Express
- **Task Queue:** Celery with Redis (for long-running scans)
- **Database:** SQLite or PostgreSQL (for storing scan history and results)
- **External Tools:** Nmap, RustScan, Masscan, Fping, Netdiscover (optional, installed on server)

**Frontend:**
- **Framework:** React.js or vanilla JavaScript with modern ES6+
- **Graph Visualization:** Cytoscape.js for interactive network graphs
- **Styling:** Custom CSS with dark theme (GitHub-inspired #0d1117 palette)
- **Charts:** Chart.js for result visualizations and statistics
- **Real-time Updates:** Server-Sent Events (SSE) or WebSockets for live scan progress

**Deployment:**
- **Option 1:** Self-hosted (Docker container with nginx reverse proxy)
- **Option 2:** Cloud deployment (AWS, DigitalOcean, etc.)
- **Option 3:** Local network appliance for internal security teams

### 3. Tool Panel (Main Content Area)

Each tool has a dedicated panel with the following structure:

**Header:**
- Tool title (large, bold)
- Short description (muted text)
- Separator line

**Input Fields:**
- Target input (domain, IP, or URL) with placeholder
- Configuration options (dropdowns, checkboxes, number inputs)
- Tool-specific parameters (e.g., record types for DNS, port ranges for scans)
- Inline hints for complex fields

**Action Buttons:**
- Primary: "▶ Run" (runs the tool, shows live progress)
- Secondary: "⬡ Add to Graph" (adds results to interactive graph)
- Tertiary: "📋 Copy Results", "⬇ Export JSON"

**Live Progress Indicator:**
- Shows scan status: ● Running, ✓ Completed, ✗ Failed
- Progress bar for long-running scans (Nmap, RustScan, etc.)
- Elapsed time counter
- Cancel button for active scans

**Results Display:**
- Structured, formatted output (not raw CLI text)
- Color-coded sections (🟢 success, 🔴 errors, 🟠 ports/IPs)
- Expandable/collapsible result sections
- Copy button for each result section

## Complete Tool Specifications

### DNS Tools (4 Tools)

#### 1. DNS Lookup
**Purpose:** Query DNS records for a domain
**Inputs:**
- Target (domain): `example.com`
- Record Types (checkboxes): A, AAAA, MX, NS, TXT, CNAME, SOA
**Output:** Grouped records by type with counts
**Graph Nodes:** Target → A/AAAA/MX/NS/TXT records
**API:** dnspython (or socket fallback)

#### 2. Reverse DNS
**Purpose:** Find hostname for an IP address
**Inputs:**
- Target (IP): `93.184.216.34`
**Output:** Hostnames list
**Graph Nodes:** IP → Hostname nodes
**API:** dnspython PTR lookup

#### 3. Find Subdomains
**Purpose:** Discover subdomains via certificate transparency and brute-force
**Inputs:**
- Target (domain): `example.com`
- Use CRT.sh (checkbox): ☑ Certificate Transparency
- Use Brute-Force (checkbox): ☑ Common Wordlist
**Output:** Sorted subdomain list with count and methods used
**Graph Nodes:** Domain → Subdomain nodes (green)
**API:** crt.sh API + DNS brute-force

#### 4. Find Shared DNS
**Purpose:** Find domains sharing nameservers
**Inputs:**
- Target (domain): `example.com`
**Output:** Nameservers with IPs, shared domains per NS
**Graph Nodes:** Domain → NS → Shared domains
**API:** DNS NS resolution + HackerTarget API

---

### Network Tools (6 Tools)

#### 5. Test Ping
**Purpose:** Test reachability and latency
**Inputs:**
- Target (host/IP): `example.com`
- Count: `4`
**Output:** Reachability status, packets sent/received, loss %, RTT stats (avg/min/max/mdev)
**Graph Nodes:** Target → Reachable (green) / Unreachable (red)
**API:** System ping command

#### 6. Traceroute
**Purpose:** Trace network path to target
**Inputs:**
- Target (host/IP): `example.com`
- Max Hops: `30`
**Output:** Hop list with IPs, hostnames, response times
**Graph Nodes:** Target → Hop 1 → Hop 2 → ... → Target IP (bubble visualization)
**API:** System traceroute/tracert command

#### 7. TCP Port Scan
**Purpose:** Scan for open TCP ports
**Inputs:**
- Target (host/IP): `example.com`
- Port Range: `1-1024` (or custom like `80,443,8000-9000`)
- Timeout: `1.0s`
- Threads: `100`
**Output:** Open ports with service names and banners
**Graph Nodes:** Target → Port nodes (red) with service labels
**API:** Multi-threaded socket connect scan

#### 8. UDP Port Scan
**Purpose:** Scan for open UDP ports
**Inputs:**
- Target (host/IP): `example.com`
- Ports: `53,67,68,123,161,500,514` (or custom)
- Timeout: `2.0s`
**Output:** Open/filtered ports with state and service
**Graph Nodes:** Target → UDP port nodes (orange)
**API:** UDP socket probes

#### 9. Subnet Lookup
**Purpose:** Analyze CIDR subnet
**Inputs:**
- Target (CIDR): `192.168.1.0/24`
**Output:** Network address, broadcast, netmask, usable hosts, first/last host
**Graph Nodes:** Network → Sample IPs
**API:** Python ipaddress module

#### 10. Banner Grabbing
**Purpose:** Grab service banners from ports
**Inputs:**
- Target (host/IP): `example.com`
- Ports: `21,22,25,80,443,8080`
- Timeout: `3.0s`
**Output:** Port/service/banner or error for each port
**Graph Nodes:** Target → Ports with banner text
**API:** Socket connections with HTTP HEAD probe

## Security Considerations

### Backend Security
1. **Rate Limiting:** Limit scan requests per user/IP
2. **Input Validation:** Sanitize all target inputs (prevent command injection)
3. **Authentication:** JWT-based auth for multi-user deployments
4. **API Key Encryption:** Store API keys encrypted in database
5. **Scan Restrictions:** Whitelist/blacklist target ranges (prevent scanning unauthorized IPs)
6. **Timeout Enforcement:** All scans have maximum timeout limits
7. **Audit Logging:** Log all scans with user, target, timestamp

### Frontend Security
1. **CSP Headers:** Content Security Policy to prevent XSS
2. **HTTPS Only:** Force HTTPS in production
3. **CSRF Protection:** CSRF tokens for all POST requests
4. **Input Escaping:** All user inputs escaped before display (use graphEsc() equivalent)

## Key Implementation Notes

1. **All tool functions return structured dictionaries** (not raw text) for consistent graph rendering
2. **Graph extraction happens server-side** but rendering is client-side (Cytoscape.js)
3. **Scan results are persistent** - stored in database for later review
4. **Bulk operations run sequentially** with configurable delays to avoid rate limiting
5. **External tools are optional** - app checks availability at startup and disables unavailable tools
6. **API keys are optional** - all tools work without keys, but enhanced features (Shodan, etc.) require them
7. **Dark theme is default** - light theme available as toggle
8. **All JavaScript uses graphEsc() equivalent** to prevent XSS in rendered HTML
9. **Traceroute parsing extracts hops from raw output** - no separate structured field needed
10. **Module loader groups by category** - makes it easy to find and select related scans
